# Build status

## Launcher foundation
- Electron + TypeScript project: dark blue/purple interface with Home, Mods, Cosmetics, Accounts, and Settings. PLAY now starts the installation/authenticated launch workflow, with progress and an in-memory game log. Build and automated shell smoke test pass; no authenticated Minecraft launch has been verified.
- Browser-based Microsoft authorization code + PKCE, Xbox/XSTS and Minecraft token exchanges, Java entitlement check and profile retrieval are implemented using the supplied public client ID. Mocked protocol tests pass; real sign-in, application approval and ownership checks are unverified. Tokens are held only in memory, without refresh or persistence.
- Accounts supports adding, switching, signing out and removing the one in-memory account. Removing asks for confirmation; sign-out/removal clear the launcher session and invalidate an in-progress sign-in. Each OAuth request creates fresh state and PKCE values and requests `prompt=select_account`; browser-managed Microsoft sessions are separate. During the latest inspection no NicoClient credential files were identified; none were deleted.
- In a real sign-in attempt, the user reported HTTP 403 at the Minecraft Services `/authentication/login_with_xbox` exchange, after Microsoft and Xbox/XSTS responses. The ownership and profile checks were not reached. The configured relying party and request format match the documented flow, but the issued token's actual audience and application approval status have not been verified; the 403 alone does not establish the cause. The original response body was not retained. New diagnostics retain only validated numeric error codes and an explicit allowlist of known harmless service error types/messages; arbitrary response text is discarded. A fresh interactive attempt is required to obtain any recognized service detail.
- The launcher creates `%APPDATA%\NicoClient` and its `mods`, `config`, `resourcepacks`, `shaderpacks`, and `logs` folders on startup. The NSIS installer is configured to create the same folders for the installing user.
- Modrinth search, dependency-aware installation with SHA-512 and size checks, mod listing/toggling/uninstalling, update checks and progress are implemented. A live Sodium search/download into a temporary test directory and mocked dependency/corruption tests passed. Automatic mod update replacement is not implemented; unknown local mods and incompatibilities require manual review. In-game loading is untested.
- Free cosmetic preference controls persist locally; Fabric-side rendering for capes, wings, particles, HUD and animations is not implemented.
- GitHub `electron-updater` integration targets `Nicoweyin/NicoClient` with manual download and restart confirmation. The corrected-owner unsigned installer, blockmap and `latest.yml` are in `release-corrected/`; the embedded provider and installer metadata were checked. Earlier `release/` artifacts retain the old owner. Installation and updater delivery from a published release have not been tested; see `RELEASE.md` for signing limitations.
- Windows branding uses `NicoClient` for the Electron app name, window title, packaged executable and NSIS shortcut, with AppUserModelID `dev.nicoweyin.nicoclient` and the original pickaxe icons. A temporary NSIS install confirmed executable metadata, shortcut target/ID and the installed window title; its test shortcut and registration were removed afterward without deleting NicoClient game data. The taskbar context menu has not been visually verified. Development mode uses the generic Electron executable, whose Windows executable metadata may still say Electron.
- Original diamond-pickaxe icon generated in PNG and ICO formats; existence verified. Visual icon verification, splash screen, real-account authentication verification, real game launch, and profiles: pending.
- A separate `fabric-mod/` client-only project targets Minecraft 1.21.11, Fabric Loader 0.20.1 and Fabric API 0.141.6+1.21.11 using official Mojang mappings. FPS, Keystrokes, the Right Shift screen, category filter, favorites, persistent settings, HUD editor, Zoom, Low Fire, Fullbright, Reduced Particles and approximate Trajectories compile with Loom 1.19.3 and Gradle 9.8.2. The remapped jar is `fabric-mod/build/libs/nicoclient-fabric-0.1.0.jar`. No in-game test has verified the screen, mixins, controls, persistence, predictions or appearance. See `fabric-mod/LOCAL_TESTING.md` for limitations and test steps. Remaining requested modules and broader settings are pending.
- The Windows x64 PLAY workflow downloads official Minecraft version metadata, libraries and assets with SHA-1/size checks, installs Fabric Loader 0.20.1, resolves Fabric API via Modrinth with SHA-512 verification, copies the built NicoClient JAR without overwriting a different file, rechecks ownership and session expiry, and starts Java in `%APPDATA%\NicoClient`. A real metadata/files download and Fabric API install succeeded in temporary directories. The combined authenticated launch, Java native loading, Fabric mod loading and user-folder installation remain untested.
- Java 21+ is required via `JAVA_HOME` or PATH. The launcher passes the Minecraft token to a separate bootstrap through a standard-input pipe rather than the Java command line, and redacts displayed game output. A mock entry-point test passes; a real Minecraft launch remains unverified. Sign-in and entitlement verification depend on Minecraft Services app approval. No refresh token is persisted; expired sessions require sign-in again.

## Latest improvements (2026-11-04)
- PLAY no longer blocks when Fabric API publishes a new release, when the NicoClient JAR is rebuilt, or when a game file is damaged (the damaged file is kept with a `.damaged` suffix and downloaded again). Temporary download failures are retried.
- PLAY installs Mojang's official Java runtime automatically, with system Java as the fallback. A real download of the 402 runtime files into a temporary folder succeeded and `java -version` reported 21.0.7. It has not yet been used for a real authenticated launch.
- Settings has a saved memory slider, and the launcher stays alive while Minecraft runs. Home has a stop button, account status and a copyable log. Mods can be updated in one click; a failed update restores the old file.
- The official launcher profile can be set up from the Home page. This shares its code with `scripts/setup-official-profile.cjs`, and it has not been run against a real `.minecraft` folder.
- The Fabric mod has nine new HUD modules, and the HUD editor handles all of them. `gradle runClientGameTest` is the first test that runs the mod in a real client; see `FEATURES.md` for what it covers. The HTTP 403 at Minecraft Services is unchanged because it is not a code problem.
